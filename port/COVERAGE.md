## Method

- Python defs: every top-level `def` and every method of a top-level class in `fsv/src/fsv/**/*.py`, listed with `ast`. Nested defs, such as the per-resource commands built inside `cli._make_subapp`, are not listed.
- Rust fns: only files reachable through `mod` declarations from `src/lib.rs`, `src/main.rs` or `tests/*.rs` of a crate that compiled. Fns in `#[cfg(test)]` modules and integration tests count as test code, not as implementations.
- Matching: snake_case name with leading underscores stripped, ranked by expected crate and file for the Python module, `impl` type equal to the Python class, and doc comments citing the Python name. Typer commands are matched through the `dispatch` match arms in `fsv-cli` (command path to fn). When no exact name matches, two fallbacks apply, both limited to the expected crate: a fn whose doc comment opens with the Python name in backticks, and a unique fn in the expected file whose name extends the Python name (`fields_from` to `fields_from_payload`).
- Stubs count as missing: fns in `fsv-cli/src/pending.rs`, any fn calling `not_ported`, `todo!` or `unimplemented!`, handlers that call `pending::*`, and inline dispatch arms (no fn of their own).
- Test evidence: the fn name is called or referenced in a `#[test]` fn, a test-module helper or an integration test file. Common names such as `new`, `get` or `render` only count when the test is in the same file or module, or names the `impl` type. CLI command fns also count when a `fsv-cli/tests` argv runs that command path; such a test may only reach argument validation.
- Limits: matching is by name. A port renamed beyond the fallbacks above shows as missing, and an unrelated fn with the same name in the expected crate can show as a match. "reached indirectly" notes come from a name-based call graph within one crate and are hints only.
- n/a covers Textual hooks (`compose`, `on_mount`, `watch_*` and similar) on Textual subclasses, the lazy-import `__getattr__` shim, and dunder methods whose class exists as a Rust type. These are only applied when no Rust fn matched.
- The Rust TUI and form UI route events through message enums (`App::on_msg`, `App::on_ui`) instead of one method per Textual `action_*` or `on_*` handler. Those handlers are listed as missing unless a Rust fn shares the name, even when the behaviour lives in a match arm.

Build check: `cargo build --workspace --tests --offline --keep-going` exit 0; crates whose lib/bin test target built: fsv-api, fsv-app, fsv-cli, fsv-completion, fsv-core, fsv-flows, fsv-forms, fsv-formui, fsv-py, fsv-tui, fsv-views.

Orphan `.rs` files (not in any `mod` chain, not counted): `fsv-core/src/client/html.rs`.
